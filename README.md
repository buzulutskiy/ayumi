# Разбег

Одностраничное веб-приложение: бег без расписания. Приложение показывает одно следующее занятие, собирает его из твоего прошлого опыта и откладывает набеганное по Карельскому перешейку.

Живёт здесь: **https://buzulutskiy.github.io/razbeg/**

Весь код — в `index.html`. Ни библиотек, ни сборки, ни запросов на сторону (кроме синхронизации, если её включить). Данные лежат в `localStorage`.

## Как поставить на iPhone

Открыть ссылку в Safari → Поделиться → «На экран „Домой“». Дальше запускается как приложение, без адресной строки, и работает офлайн.

## Без настройки и без расписания

Онбординга нет: приложение сразу показывает первое занятие — 8 минут бега отрезками по минуте.

Расписания тоже нет — ни недель, ни дней. Есть **одно следующее занятие**, которое собирается заново после каждой загруженной пробежки. Бежать можно в любой день; пропуск ничего не ломает.

## Всё в минутах

У часов ровно один интервальный блок: работа, отдых, количество повторов, разминка вручную. Поэтому каждое занятие — ровно одна такая тройка:

```
Разминка   5 мин шагом
Работа     1:00
Отдых      1:30 шагом
Повторов   8
Заминка    5 мин шагом
```

Километры получаются сами собой и нужны только для маршрута.

## Как собирается следующее занятие

Всё держится на одном числе — **уровне**: сколько минут бега сейчас посильно за занятие. Уровень нигде не хранится, а пересчитывается из всей истории (`levelNow`).

**Двигают его ответы на единственный вопрос** — как далась пробежка. Приложение задаёт его после каждой загрузки файла:

| ответ | что делает с уровнем |
|---|---|
| Легко | +14% |
| Нормально | +7% |
| Тяжело | оставляет как есть |
| Очень тяжело | −12% |

Больше 14% за занятие уровень вырасти не может. Это не осторожность ради осторожности: по [когортному исследованию BJSM на 5200 бегунах](https://marathonhandbook.com/the-10-rule-new-study-suggests-weve-been-doing-it-wrong-this-whole-time/) резкий скачок одной пробежки предсказывает травмы лучше, чем прирост недельного объёма. Перерыв больше двух недель откатывает уровень на 15%, больше месяца — на 30%.

**Типы чередуются**: интервалы → непрерывный бег → интервалы. Интервалы учат держать темп, непрерывный бег — держаться дольше. Непрерывное занятие берётся как 75% от уровня: без пауз то же время даётся тяжелее. Длина рабочего отрезка в интервалах растёт вместе с уровнем — от 1 минуты до 8 (`INT_TABLE`).

## Индекс бегуна

Из файла приходят только дистанция и время, поэтому индекс считается по тому, что из них выводится, — оценке МПК по формулам [Дэниелса и Гилберта (1979)](https://runbundle.com/tools/vo2-max-calculators/vo2-max-calculator):

```
VO₂  = −4.60 + 0.182258·v + 0.000104·v²          v — метров в минуту
%max = 0.8 + 0.1894393·e^(−0.012778·t) + 0.2989558·e^(−0.1932605·t)
VDOT = VO₂ / %max                                 t — минут
```

Проверка: 5 км за 20:00 даёт 49,8 — ровно то, что в таблицах Дэниелса.

Считается по самому быстрому **непрерывному** бегу за последние 6 недель: в интервальном занятии средний темп размазан ходьбой и сравнивать его не с чем. Рядом два отдельных показателя — выносливость (максимум минут подряд) и лёгкий темп (медиана по пробежкам, отмеченным «легко» или «нормально»). Каждый сравнивается с предыдущими шестью неделями и показывается как «лучше / без изменений / хуже»; порог в 2–5% нужен, чтобы шум не выдавался за рост.

Число занижено, если человек ни разу не бежал в полную силу. Поэтому важна не величина, а направление.

## Загрузка пробежек

Фильтра по типу файла **нет намеренно**: в «Файлах» на iPhone `accept` гасит всё, что не совпало по MIME, а приложения часов отдают что попало. Формат определяется по содержимому, а не по расширению (`ingestBuf`):

- **PK…** — zip. Разбирается свой минимальный распаковщик: центральный каталог плюс `DecompressionStream('deflate-raw')`, дальше каждый файл внутри обрабатывается рекурсивно.
- **`<`** — XML: TCX (дата в `Id`, дистанция и время в `Lap`) или GPX (длина по трекпоинтам формулой гаверсинуса).
- **`{` / `[`** — JSON произвольной формы. Дерево обходится рекурсивно, ищутся объекты с полями даты, дистанции и длительности; метры переводятся в километры, секунды в минуты, эпоха в дату.
- иначе — CSV, включая `activities.csv` из архива Strava.

Можно выбрать сразу несколько файлов. Велосипед, плавание и ходьба отсеиваются. Дубли режутся по паре «дата + дистанция», так что один и тот же файл можно грузить повторно.

## Синхронизация

«Ещё» → «Подключить гист». Нужны номер приватного гиста и токен GitHub с одной областью `gist`. Токен хранится только в `localStorage` этого браузера, в репозитории его нет и быть не должно.

После каждой загрузки файлов данные уезжают в гист, при запуске забираются обратно. Пробежки сливаются объединением по ключу «дата + дистанция», поэтому телефон и компьютер сходятся к одному состоянию без ручного разбора конфликтов.

## Маршрут

`ROUTES` в `index.html` — один маршрут по Карельскому перешейку: от северной окраины города вдоль Финского залива на Выборг, затем поперёк перешейка к Ладоге и обратно вдоль неё к городу. 385 км, 39 мест.

Дорога открывается по мере бега. Пройденные места показаны с фактом, ближайшее — только названием, остатком километров и прогнозом, всё остальное закрыто и считается общим числом. Прогноз (`routeEta`) строится на медианной длине пробежки и медианном промежутке между ними: «ещё 3,1 км — это примерно 1 занятие и 3 дня, к 16 августа».

Чтобы продлить путь, достаточно дописать остановки в конец списка: абсолютные километры считаются автоматически.
